# 🧊 冷蔵庫レシピ

冷蔵庫にあるものを登録しておくと、

- **いま作れる** 献立（不足0品）
- **ちょい足しで作れる** 献立（「豚肉を買うと、あと7品」）

を出してくれるアプリです。**インストール不要・登録不要**、開いてすぐ使えます。

👉 **https://g0212arc.github.io/fridge-recipe/**

スマホでこのURLを開いて「ホーム画面に追加」すると、アプリのように使えます。
一度開けばオフラインでも動きます。

## 特徴

- **サーバーがありません。** 冷蔵庫の中身はあなたの端末の中だけに保存されます。
  こちらからは何も見えませんし、どこにも送信されません
- **159件の献立を同梱。** アカウント登録もAPIキーも不要
- **賞味期限が近い食材を優先。** 「あと1日」の鶏肉を使うレシピが上に出ます
- **手順は各サイトへ。** クックパッド・味の素パークほか6サイトへ、
  冷蔵庫の中身から組み立てた検索リンクで飛べます

## 使い方

1. **冷蔵庫タブ** で食材を追加する（賞味期限は任意）
2. **レシピタブ** に切り替える

それだけです。

### 常備品について

醤油・塩・砂糖などは「いつもある」前提で、不足食材に数えていません。
これを数えると、ほとんどの献立が「調味料が足りない」で脱落してしまうためです。

切らしているものは **冷蔵庫タブ → 常備品の設定** から外してください。

## レシピの出どころ

同梱しているのは、出典を持たない一般的な家庭料理を書き起こしたものです。
レシピサイトからの転載ではありません。手順は各サイトの検索へ誘導しています。

**クックパッドと味の素パークは公開APIが無く、規約でも自動収集が禁止されている**ため、
このアプリはそれらのサイトからデータを取得しません。検索URLを組み立てるだけで、
アクセスはあなたのブラウザから発生します。

### レシピを増やす（任意・自分用）

楽天レシピAPIから実在レシピを取り込めます。無料のアプリIDが必要です。

```bash
export RAKUTEN_APPLICATION_ID=xxxxxxxx    # https://webservice.rakuten.co.jp/ で取得
export RAKUTEN_ACCESS_KEY=yyyyyyyy

python3 tools/fetch_rakuten.py 豚肉 玉ねぎ キャベツ
```

書き出された JSON を、アプリの **レシピタブ → レシピを増やす** から読み込みます。
読み込んだデータはあなたのブラウザの中だけに残ります。

> ⚠️ **書き出した JSON は配布・公開できません。**
> 楽天ウェブサービス利用規約 第10条(9) が、取得した情報を
> 「不特定多数と共有できる場所に保存すること」を禁じています。
> GitHub に push する、友達に送る、といった使い方はできません。
> 同 第5条(2) により、アプリIDを他人に渡すこともできません。
> このため楽天レシピは「各自が自分のIDで取り込む任意機能」に留めてあります。

## 判定のしくみ

```
レシピの材料 −（冷蔵庫の食材 ＋ 常備品）＝ 不足リスト
```

材料名は `"☆醤油"` `"玉ねぎ 1/2個"` `"豚バラ肉（薄切り）"` のように揺れるので、
装飾記号・括弧・分量を落として、カタカナをひらがなに寄せてから比べます。

そのうえで、

| 条件 | 例 | 判定 |
|---|---|---|
| 表記ゆれ辞書で一致 | `玉葱` = `たまねぎ` | ⭕️ |
| どちらかが相手の総称 | 冷蔵庫 `豚肉` ／ レシピ `豚バラ肉` | ⭕️ |
| 同じ総称の兄弟同士 | 冷蔵庫 `豚バラ肉` ／ レシピ `豚ひき肉` | ❌ |
| 両方とも辞書にある別語 | 冷蔵庫 `ねぎ` ／ レシピ `玉ねぎ` | ❌ |
| 辞書に無い語同士の部分一致 | 冷蔵庫 `豆腐` ／ レシピ `絹ごし豆腐` | ⭕️ |

**「辞書に載っている語同士は部分一致させない」**のが肝で、
これが無いと `ねぎ` が `玉ねぎ` を満たしてしまいます。

並び順は、使う食材が多いほど・賞味期限が近いほど上に来ます。

## デプロイ

`main` に push すると GitHub Actions がビルドして GitHub Pages に公開します。

Pages の有効化はワークフローが自分で行うので、設定画面での操作は要りません。

ただし **リポジトリが公開であること**が前提です。無料プランでは
プライベートリポジトリで GitHub Pages を使えません（有料の Pro 以上が必要）。
非公開のまま配信したい場合は、Cloudflare Pages や Netlify を使ってください。

## 開発

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 75件。ブラウザもネットワークも使いません
npm run build
```

```
src/
  core/            画面に依存しないロジック（ここだけでテストが完結する）
    normalize.ts   正規化・同義語・総称
    matching.ts    充足判定とスコアリング
    links.ts       各サイトの検索URL生成
    recipes.ts     レシピ集の読み込み
    types.ts
  data/
    recipes.json      同梱レシピ集（159件）
    ingredients.json  表記ゆれ辞書（150の代表名）
    generics.json     総称と個別（豚肉 ⊃ 豚バラ肉）
    seasonings.json   常備品の初期値
  ui/              画面（localStorage 保存）
tools/
  fetch_rakuten.py 楽天レシピ取り込みCLI（任意・自分用）
```

### 辞書とレシピを育てる

うまくマッチしない食材があれば `src/data/` を直してください。
`npm test` が同梱データの健全性（材料が消えていないか、表示が崩れないか、
常備品だけのレシピが無いか）を確認します。

- `ingredients.json` … 代表名と別名（`"玉ねぎ": ["玉葱", "タマネギ", ...]`）
- `generics.json` … 総称と個別。`groupLabel` を立てると「〜を買うと」の見出しにまとまる
- `recipes.json` … 献立。`materials` は普段の言い方でそのまま書けば正規化されます
